CE QUI NE DOIT **PAS** ÊTRE ENVOYÉ
--------------------------------------------------------------------
- La clé service_role de Supabase : jamais, dans aucun fichier.
- Le mot de passe de la base de données Supabase.
- Les guides de publication (dossier « mes-guides ») : ils sont
  destinés à votre usage personnel, pas aux visiteurs du site.
- La version locale du site (visiteur.html, app.js…) qui fonctionne
  sans serveur : c'est un projet séparé.

--------------------------------------------------------------------
SITE DÉJÀ PUBLIÉ ? MISE À JOUR v3 (favoris, réservé, notation, photo de profil…)
--------------------------------------------------------------------
1. Supabase → SQL Editor : collez TOUT supabase-schema.sql → Run.
   (Le script se relance sans risque : aucune donnée n'est effacée.)
2. GitHub : remplacez supabase-schema.sql, api.js, style.css,
   index.html, membre.html, administrateur.html, README.md,
   et ajoutez CORRESPONDANCE-RAPPORT.md.
   Vercel redéploie automatiquement.

--------------------------------------------------------------------
LES TROIS ÉTAPES, DANS L'ORDRE
--------------------------------------------------------------------
1. Supabase : créer le projet, exécuter supabase-schema.sql,
   copier les deux clés dans config.js.
2. GitHub : créer un dépôt public « bookswap » et téléverser
   ces fichiers.
3. Vercel : Add New -> Project -> Import « bookswap » -> Deploy.
   Puis reporter l'adresse obtenue dans Supabase
   (Authentication -> URL Configuration).

Détail complet : ouvrez guide-fr.html ou guide-ar.html depuis le
dossier « mes-guides », sur votre ordinateur.
